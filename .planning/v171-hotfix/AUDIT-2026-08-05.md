# Full-app similarity audit — 2026-08-05

Scope: after the v1.7.1 hotfix (`7abf6cb`), HAN asked for a full scan for issues of
the same classes. Four parallel audits ran: HealthKit reductions, sync codec/schema,
chart domains, date/time + stale UI. Every finding below was verified in source; the
orchestrator re-verified the highest-stakes claims independently. Items marked
**FIXED (7abf6cb+1)** landed in the follow-up commit; the rest are the ranked backlog.

## Fixed in the follow-up commit

1. **Nap/night inversion in the main-session pick — regression risk from the sleep
   fix.** `fetchLastNightSleepDetail` chose `sessions.last` (most recent cluster). An
   afternoon nap is the most recent cluster, so the nap became "last night" and the
   real night was demoted to a nap candidate — cratering the live sleep number, the
   recovery score, and folding a nap into the shadow EWMAs. Fix: the night is the
   LATEST cluster with ≥180 unioned minutes (`SleepSessionMath.nightMinimumMinutes`);
   largest cluster stands in when none qualifies; nap candidates are now every
   non-chosen cluster (napMinutes bounds them itself). (This selection defect existed
   in the shadow since S2; the hotfix promoted it into the live number.)
2. **Glance charts had the same missing x-domain as the fixed detail charts.**
   `SleepTrendChart` (the purple-block twin, first thing on the Recovery tab) and
   `HRVTrendChart` (lone floating dot) now pin a trailing-28-day `chartXScale`.
3. **HRVDetailChart empty-state gate read the unwindowed series** — pinching to a
   window with no readings rendered a blank 224pt plot. Now gates on `visibleData`.
4. **Workouts pull decode hardening.** `WorkoutSessionRow` load fields + sessionType
   are now optional with `?? 0`/`?? .strength` on merge — one NULL row on the drifted
   live table can no longer fail the entire workouts pull.
5. **Migration 007 extended:** NULL backfills for pre-existing nullable columns, and
   `athletes.training_frequency` / `experience_level` (pushed by the app since
   onboarding, created by no committed migration — the athlete push fails silently
   because it has no Sync Status row).

## Backlog — HIGH (recommend next patch)

- **H1. "7-day avg" over raw HRV samples, not days.** `HRVDetailView.recent`,
  `HRVDetailChart.recent`, `HRVTrendChart.baseline` all take `data.suffix(7)` of raw
  HealthKit samples. A Watch writes several HRV samples per day, so "7d avg" is ~1–2
  days, the deviation % is compressed toward 0, and the `ND ·` stamp counts samples
  as days ("147D"). `DayBucketer` exists for exactly this and is never called from
  production. Fix: day-bucket `hrv90Days` in the ViewModels.
- **H2. Live sleep keyed on run date, not wake day.** `RecoveryRepository`
  upserts today's snapshot with `startOfDay(.now)`; a post-midnight run writes last
  night onto tomorrow's row (duplicate night in the series). Also: no guard that
  `sessionEnd` falls on today — an 00:30 open shows yesterday's night as "last
  night" with no staleness badge (17h < 24h threshold). Shadow path already does
  this correctly (wakeDay = startOfDay(sessionEnd)); mirror it in the live upsert.
- **H3. Sticky red sync rows.** `recordSuccess` fires only from pushAll/pullAll;
  pipeline- and UI-triggered pushes can only recordFailure. One transient failure
  stays red through any number of successes. Move success/failure recording into
  `run()`.
- **H4. `pullTrainingProfile` uses `.single()`** → PGRST116 permanent red row for
  any user without a cold-start profile, which also pins `shouldSync == true` →
  full push+pull every foreground. Use `.maybeSingle()`; treat no-row as success.
  Same pattern latent in bootstrapAthlete/pullAthlete (print-only).
- **H5. Template pull destroys and rebuilds every ExerciseGroup on every sync.**
  LWW guard is `>` not `>=`; after the first applied pull local == server timestamp
  forever, so the delete-all/rebuild body runs each cycle (new UUIDs each time;
  danger while a template sheet is open). One-char fix at seven pull sites + a
  diff-merge for groups.
- **H6. Deletion resurrection.** Full-upsert, no tombstones: any locally deleted
  workout/template/PR returns on the next pull. Needs `deleted_at` soft-delete.
  Largest change; schedule deliberately.
- **H7. `bootstrapAthlete` conflates "not found" with transport error** → reinstall
  on bad network = zombie sign-out; Apple Sign-In re-auth can reset displayName to
  "Athlete" and push it over the server row. Make it throw/Result and branch only on
  a genuine not-found (PGRST116).
- **H8. Streak collapses to 0 every Monday.** `StreakEngine` treats the in-progress
  week's absence as a broken streak. Don't break on the current week.
- **H9. "Last used in 0 seconds" on template cards.** `TemplateCarouselSection:233`
  and `TemplatePickerSheet:110` use `.formatted(.relative(...))` — the same defect
  as the fixed Sync Status stamp, visible right after finishing a template workout.
  Route through a shared just-now-floored helper.
- **H10. RecoveryView never re-evaluates "today".** No scenePhase /
  NSCalendarDayChanged hook: after an overnight background, the morning check-in
  prompt stays hidden and yesterday's snapshot renders as today. Copy the
  DashboardView/WorkoutLogView idiom.

## Backlog — MEDIUM

- M1. Athlete pull restores only 4 of 11 pushed fields (not even sportType);
  weightUnit/acwrMethod/loadMetricPreference/maxHeartRate/dateOfBirth are
  write-only. New-device restore silently loses settings.
- M2. `InviteService` + `TemplateSharingService` Decodable structs use snake_case
  property names under the `.convertFromSnakeCase` decoder → every decode throws
  keyNotFound (invite redemption and share-code import are dead). NOTE: both are
  athlete-only-era edge features; decide whether to fix or retire the surfaces.
- M3. behavior_tags: repo has no DDL (docs debt — the live table exists, both
  directions sync green); pull drops the wellnessCheckIn link and check-in save
  delete-and-recreates with fresh UUIDs → server rows accumulate, orphans skew
  BehaviorCorrelationEngine. Also `BehaviorTagRow.date` is plain `Date` — safe
  only while the live column is timestamptz.
- M4. `training_profiles` upsert conflicts on PK while the table is
  UNIQUE(athlete_id) → 23505 on a second device. Use `onConflict: "athlete_id"`.
- M5. No UNIQUE(athlete_id, date) on daily snapshot tables → two devices create
  duplicate day rows; `fetchTodaySnapshot` has no sortBy → nondeterministic hero
  score. Add the constraint + onConflict; make equality upserts half-open ranges
  (MockDataSeeder writes unfloored dates — SCREENSHOT_MODE can duplicate rows
  today).
- M6. `DateOnly`/`postgresDay` formatters freeze `TimeZone.current` at first use;
  a mid-flight timezone change day-shifts encodes until relaunch. Set `.timeZone`
  per call.
- M7. `fetchLatestBodyTemp`/`fetchLatestVO2Max` have no date bound and no staleness
  channel (months-old readings presented as current); wrist temp and core temp
  collapse into one field.
- M8. Same-day pipeline re-run includes today's own row in the 7-day baseline →
  score drifts between the first and second run of the day. Exclude today from the
  baseline query.
- M9. RecoveryLoadChart: recovery series invisible below 2 points (no .symbol),
  scaleFactor divides toward 0 on an all-zero load week, no x-domain, scrub reaches
  load days only.
- M10. Load trend section renders header + range control over nothing when
  `trendData.count <= 1` — add the insufficient-data message.
- M11. Detail-screen subtitle says "28-day …" while the stamp above it says "1D ·"
  — consider driving the subtitle from visible data or dropping it when sparse.

## Backlog — LOW / hygiene

- L1. Unconstrained x-axis tick granularity (repeated "AUG 4" labels) — set
  `AxisMarks(values: .stride(by: .day, count: n))` on all six charts.
- L2. `%.0f` y-labels duplicate on tight domains; no chartYScale anywhere.
- L3. `daysAgo` counts 24h blocks, not calendar days (staleness under-reports by
  one day); no badge at all when data is older than the fetch window.
- L4. `HeroReadinessCard.dateLabel` and `todayISOWeekday` go stale across a
  foreground midnight (no NSCalendarDayChanged on Dashboard).
- L5. Dead HealthKit surface: fetchLatestHRV/RestingHR, fetchRestingHRHistory,
  fetchWorkoutHeartRates, calculateTRIMP, fetchStaleness — zero callers; `.stepCount`
  read permission requested and never used. Migration probe no longer fires for
  inBed-only legacy data (accepted).
- L6. Stage/inBed intervals admitted whole into the session union (not clipped) —
  inflates shadow inBed/WASO for long-spanning samples.
- L7. CycleTrackingService biphasic shift averages 5 samples, not 5 days.
- L8. Push uploads every row of every entity each cycle (no updatedAt watermark).
- L9. Weekly summary uses a rolling 168h window while StreakEngine uses ISO weeks —
  two different "week"s on one card.
- L10. Doc drift: ChartTooltipOverlay comments describe call sites/behavior that do
  not exist; no-op `.chartLegend` on LoadTrendChartView; dead
  `WorkloadViewModel.trendSnapshots`.
