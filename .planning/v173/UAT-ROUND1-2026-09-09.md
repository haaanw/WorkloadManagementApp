## R1-product lane record (2026-09-09)

Appended by the R1-product lane. The R1-fix lane owns everything above this rule;
nothing there was edited.

### U4 · why recent watch workouts were missed — DIAGNOSED, four defects

Ruled out first: **authorization is not the cause.** `HKWorkoutType.workoutType()`
has been in `readTypes` since `a96941a` (2026-04-21), long before HAN's grant, and
the three walks proved reads were working.

Four defects, all in the retired `WorkoutImportService`, ranked by how well each
explains "three stale walks with the recent session missing":

1. **The list was fetched once per app process and never again.** `.task` on the
   Log tab (`WorkoutLogView.swift:434`) is the only trigger. In a `TabView` the
   child is built on first selection and kept, so the task never fires a second
   time — no foreground refresh, no observer, no anchor. A watch workout reaches
   the phone's HealthKit store MINUTES after it ends, routinely after that one
   fetch has already run, and nothing asked again. **This is the primary cause**
   and it is the only one that also explains why the list looked frozen.
2. **A three-day window with no catch-up.** The service defaulted to 7 days; the
   call site passed 3 (`WorkoutImportBanner.swift:203`). Anything older was
   invisible permanently.
3. **Everything under five minutes was discarded** (`:233`) — a short sprint block
   or skill session never appeared at all.
4. **The dedupe was a POINT match** — suppress if any session started within five
   minutes (`:226-230`). It failed in both directions: a watch started ten minutes
   into a logged session read as a second session (double-counted load), and two
   genuinely different sessions four minutes apart lost one silently.

**Not determinable from source:** which of 1/3/4 hit HAN's specific missing
workout. Stated rather than guessed. All four are closed by the rebuild regardless.

### U4 · what was built

`WatchWorkoutMatcher` (pure) + `WatchWorkoutImportService` replace the banner, which
is DELETED. Anchored `HKAnchoredObjectQueryDescriptor` — HealthKit tracks what the app
has seen, so each workout is handed over exactly once however often the import runs;
a 14-day window bounds only the FIRST run so a new install never back-logs years of
walks. Runs on every foreground (`AppRouter`) and on the Log tab's appearance.

The dedupe guard is interval OVERLAP (≥50% of the shorter span), plus
`WorkoutSession.healthKitWorkoutUUID` as an idempotency key so a lost anchor or a
reinstall cannot double-log. It fails SAFE: a session logged twice inflates ATL, ACWR
and the fatigue index for four weeks invisibly; a session missed once is visible in
history and addable by hand.

Effort → RPE: `HKQuantityType(.workoutEffortScore)` (the athlete's own rating) with
`.estimatedWorkoutEffortScore` as fallback, both read via
`predicateForWorkoutEffortSamplesRelated(workout:activity:)`, iOS 18+. Both are 1–10
category-ratio scales asking the same question, so the map is the identity with
clamping — no invented curve on the one subjective input the load model rests on. The
fallback matters: a session with no RPE contributes ZERO internal load and zero
training stress while still counting toward session density. Raw samples stay on
device; the derived `sessionRPE` is what syncs.

A `healthKitReadTypesGeneration` counter re-asks a legacy grant once for the new
types, raised at the first moment the app actually holds a new watch workout — so the
permission sheet arrives attached to the thing it is for, not at a cold foreground.

The surface is a quiet `From watch` mark in the history row's marginalia. No banner,
no Add row, no RPE sheet.

**Scoped out, and it is a real limit: this is foreground-automatic, not background.**
True background delivery needs
`com.apple.developer.healthkit.background-delivery`, which the app does not hold
(`workload management.entitlements`) and which is a provisioning change, not a code
change. The session is already there when the athlete opens the app; it does not
appear while the phone is in a pocket. **HAN decides whether to add the entitlement.**

### U2 · the "Say it" door now speaks

Both text doors land on ONE capture surface with ONE parse path.
`SpeechCaptureService` on the `LogCaptureSheet` pattern: Record control, the
live accent dot riding the audio level, the REC clock, transcript editable

### U3 · the text surface

Keyboard-toolbar Done on the editor + drag-to-dismiss on the scroll view;
"Read my program" pinned below the editor as the step's one ink pill; the
stray "Back" deleted with its catalog key. No tap-to-dismiss on this sheet:
the editor fills it, and a tap there is a request to type.

### U5 · the metrics strip diverged in TWO ways

Width — an HStack gives a flexible child its share only while no child asks
for more, so cell widths tracked content. Three `.flexible()` columns are
equal by construction.

Type size — **the divergence HAN actually saw.** "7h 36m" is ~108pt at the
32pt display face, wider than an equal third of the strip, so the sleep
reading spent its `minimumScaleFactor` and rendered several points smaller
than HRV/RHR. It takes the clock form now ("7:36") with the hour in the
annotation slot, where v6 says units belong. `durationString` is untouched
everywhere else.

### U6 · header and keyboard (mechanical half only)

`SheetHeaderLayout` gives both action slots the wider one's width, so the
title centres in the whole bar and can never be overdrawn; actions are never
truncated. The slots read Cancel / Save. `FormField` contributes a
keyboard-toolbar Done while focused; Profile and the profile sheet add
drag-to-dismiss and a tap on the page. `dismissesKeyboardOnTap` is a plain
`.onTapGesture` — a `simultaneousGesture` would resign the very field the
tap was focusing. **Sports multi-select was NOT touched** (product lane).

### U11 · many files, one program

Both pickers go multi-select (`maxSelectionCount` / `allowsMultipleSelection`
— no new dependencies). Extraction runs per file at PICK time through the
existing text-layer/OCR paths, so an unreadable page names itself while the
athlete can still act on it and the rest of the batch stands. The files then
show as a removable list — with "Add more", since removal alone still forces
a restart when the pick was too small — before anything is parsed.

`WorkoutLLMImportService.combineProgramFiles` joins the texts in the
athlete's own order behind "— file 2 of 3 —" markers, and the whole thing
takes a SINGLE program-mode parse. Parsing per file would show the model
three fragments and let it stitch the weeks back together wrong. The markers
carry words on purpose so B1's furniture pass cannot strip them. The
combination takes preprocessing as one document, so furniture is stripped
BEFORE the 60k cap is measured; still over, the client-side guard raises the
"a few weeks at a time" prompt (re-worded for a batch) and the server never
answers with a bare 400. Seven unit tests cover order, markers, marker
survival, the empty and single-file edges, and the cap.

### Found, NOT fixed — out of lane, needs HAN

`InstrumentSheetHeader(title:) { … }` with no `trailing:` binds its trailing
closure to `trailing`, not `leading` (Swift's deprecated backward matching,
warned in **seven** sheets). CANCEL therefore sits on the RIGHT in all seven
and on the LEFT in `TrainingProfileSheet`, which labels the argument. Latent,
pre-existing, and an error in a future Swift. The fix is one line per file —
but it moves CANCEL on seven screens, so it wants HAN's eye, not a silent
change inside a UAT fix round.
