## Spacing Scale

Declared values (8pt base, per DESIGN.md):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 8pt | Icon-label gaps, inline padding, set row internal gaps |
| sm | 16pt | Card internal padding (horizontal), picker sheet margins |
| md | 24pt | Card internal padding (vertical), exercise group spacing |
| lg | 32pt | Section gaps between template picker sections |
| xl | 48pt | Major section breaks |
| 2xl | 64pt | Page-level top/bottom breathing room |

Exceptions: 44pt minimum touch target for "Fill last" / "Fill suggested" buttons (iOS HIG requirement, achieved via frame height on 8pt-padded content).

## Interaction Contracts

### Template Picker Flow

1. User taps "+" on WorkoutLogView
2. `TemplatePickerSheet` presents as `.sheet` with `surfaceEl` background
3. Sheet shows grid/list of template cards + "Start blank workout" button at bottom
4. Tapping a `TemplatePickerCard` dismisses sheet and opens `ActiveWorkoutSheet` pre-filled from template
5. "Start blank workout" dismisses sheet and opens `ActiveWorkoutSheet` with no template (existing behavior)
6. When zero templates exist: show empty state card with "Create your first template" CTA + "Start blank workout" button

### Ghost Target Display

1. Template-loaded `ActiveWorkoutSheet` renders exercises from template groups
2. Each weight/reps/RPE field shows last-used actual value as `ColorTokens.text3` placeholder text at `Font.Tokens.label` (15pt)
3. Field value is empty (no text in the field itself) -- ghost is placeholder only
4. User types to override ghost value with actual input
5. Ghost values are NOT auto-saved if user does not interact

### Fill Mechanisms

1. **Keyboard enter/submit** on any empty field in a set row: auto-fills weight + reps + RPE for that row with last-session values
2. **"Fill last" button** in `FillButtonBar`: fills ALL rows across ALL exercises with last-session values
3. **"Fill suggested" button** (Pro only) in `FillButtonBar`: fills ALL rows with ProgressionEngine suggestions
4. `FillButtonBar` positioned as sticky toolbar above keyboard or as inline bar below session header, above exercise list

### ProgressionEngine Overlay

1. For Pro users, after template loads, run `ProgressionEngine.suggest()` for each exercise that has prior history
2. Show suggestion as small text below the input field row: "up-arrow 85kg suggested" or "right-arrow maintain 82.5kg"
3. Style: `Font.Tokens.label` (15pt), `ColorTokens.text3`, 8pt top padding from field
4. No suggestion shown for exercises without history (fallback to template default targets as ghost)

### Quick-Start Cards (Dashboard)

1. Section appears after HeroReadinessCard, before MetricsStrip
2. Horizontal `ScrollView(.horizontal, showsIndicators: false)` with 16pt horizontal padding
3. Card order: favorited templates first, then TemplateSuggestionEngine pick (Pro, if sufficient data, no duplicates)
4. Each card: `surface` background, 0pt corners, 0.5pt `divider` border, 16pt internal padding
5. Card content: sport type SF Symbol icon (13pt) + template name (`Font.Tokens.label`, `text1`) + optional "SUGGESTED" badge
6. Card width: 140pt fixed. Card height: content-sized (approximately 72pt with padding)
7. Tap opens `ActiveWorkoutSheet` pre-filled from template
8. Section hidden entirely when athlete has zero templates

### Carousel Suggestion Labels

1. `TemplateSuggestionEngine` result highlighted in carousel with "SUGGESTED" badge
2. Badge style: `Font.Tokens.micro` (12pt), `.tracking(1.2)`, `.textCase(.uppercase)`, `ColorTokens.text2` text
3. Badge has 0.5pt border in `ColorTokens.zoneOptimal` (green zone) or `ColorTokens.zoneCaution` (if recovery-adjusted)
4. Badge positioned top-right of carousel card, 8pt inset from edges
5. "RECOVERY-ADJUSTED" badge replaces "SUGGESTED" when engine swaps to lighter template due to recovery state
6. Carousel auto-centers on suggested template (extends existing centering logic)
7. Free users: no badges, centering uses scheduledDays/lastUsedAt only (Phase 11 behavior preserved)

### Session Completion Side Effects

1. When a template-based session is saved via `FinishWorkoutSheet`:
   - Update `lastUsedAt` on source template to current date
   - Increment `usageCount` by 1
2. These updates feed into `TemplateSuggestionEngine` day-of-week frequency analysis

## State Contracts

| State | Visual Treatment |
|-------|------------------|
| Zero templates (picker) | Empty state card: "Create your first template" heading + "Start blank workout" button |
| Zero templates (dashboard) | Quick-start section hidden entirely |
| Template with no prior session history | Ghost targets show template default values (not last-used). No ProgressionEngine overlay. |
| Template with prior history | Ghost targets show last-used actuals. ProgressionEngine overlay below fields (Pro). |
| Free user viewing carousel | No "SUGGESTED" badge. Centering by scheduledDays/lastUsedAt. No "Fill suggested" button. |
| Pro user, insufficient suggestion data (< 2 weeks) | Silent fallback to scheduledDays centering. No "SUGGESTED" badge. |
| Pro user, sufficient data | "SUGGESTED" badge on recommended template. "Fill suggested" button visible. |
| Recovery-adjusted suggestion | "RECOVERY-ADJUSTED" badge replaces "SUGGESTED". Badge border uses zone caution/danger color. |
| No alternative template for recovery adjustment | Still suggest the only template. No "RECOVERY-ADJUSTED" label (no alternative available). |

## Motion Contract

All motion follows DESIGN.md constraints: no spring physics, no bounce.

| Interaction | Duration | Easing | Notes |
|-------------|----------|--------|-------|
| Template picker sheet present | 250ms | easeOut | Standard iOS sheet presentation |
| Template picker sheet dismiss | 250ms | easeIn | Standard iOS sheet dismissal |
| Ghost field fill animation | 150ms | linear | Values appear simultaneously per row |
| "Fill all" animation | 150ms | linear | All rows populate at once, no stagger |
| Quick-start card appear | 250ms | easeOut | When dashboard loads and templates exist |
| "SUGGESTED" badge appear | 150ms | linear | Applied on carousel data load |
| Carousel auto-center to suggested | 250ms | easeOut | Scroll to suggested template position |

## Accessibility Contract

| Element | Accessibility Treatment |
|---------|------------------------|
| Template picker cards | `accessibilityLabel("{name}, {exerciseCount} exercises, last used {date}")`. Button role. |
| Quick-start cards | `accessibilityLabel("Quick start {name}")`. Button role. |
| Ghost placeholder text | Announced via `accessibilityHint("Last session: {value}. Enter to fill.")` |
| "Fill last" / "Fill suggested" | Standard button accessibility. Label is the button text. |
| ProgressionEngine suggestion | `accessibilityLabel("Suggested: {weight}")` on the suggestion text view |
| "SUGGESTED" badge | Combined with parent card label: "{name}, suggested for today" |
| "RECOVERY-ADJUSTED" badge | Combined with parent card label: "{name}, recovery-adjusted suggestion" |
| Zone colors on badges | Text label ("SUGGESTED" / "RECOVERY-ADJUSTED") carries meaning -- color is supplementary only |
