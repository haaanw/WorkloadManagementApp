<objective>
Run the new `CrossModalFatigueEngine` DARK through the existing shadow-validation harness and put an explicit verdict-influence gate in front of it (ACT-02, the shadow-gating half). Per CONTEXT.md (locked: "Shadow-gate before influence") and ROADMAP SC4: the cross-modal output logs as a new prediction arm through `ShadowMetrics`/`ShadowAnalyticsService` (paired-MAE CI, Spearman, calibration, blocked-CV) and is GATED OFF from the verdict until an explicit shadow-validation PASS — the green-light is a human validation decision, not a code merge.

The harness already exists. `ShadowAnalyticsService.recordPredictions` (verified) loops `for arm in ShadowPredictor.registeredArms()` and writes one `ShadowArmPrediction` child per `(arm.id x outcome)` into `CyclePredictionLog`. Adding a fourth arm is the canonical extension point: Phase 24 shipped `baseline` + `cycleAware`, Phase 28 appended `prs` — both UNCONDITIONALLY (independent of `PRSActivation.isEnabled`). The cross-modal arm follows that exact pattern, so its predictions are logged and validated while it is fenced from any user-facing number.

This plan does NOT let the engine drive a verdict (no verdict engine exists until Phase 43) and does NOT wire it into the dashboard. It only logs it dark and gates it.

Purpose: ROADMAP SC4 — the cross-modal channel must shadow-validate before Phase 43 is permitted to consume it.
Output: the fourth shadow arm + the verdict-influence gate + tests proving existing arms stay byte-identical and the verdict gate defaults off.

DEPENDS ON Plan 02 (`CrossModalFatigueEngine` must exist).
