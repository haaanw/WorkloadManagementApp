<objective>
Build `CrossModalFatigueEngine` — the ONE genuinely new engine for v2.0 (ACT-02). It produces directional, region-resolved cross-modal fatigue carry: yesterday's run penalizes today's squat (legs) but spares today's bench (chest). `FatigueIndexEngine` is whole-body and cannot express this; the existing per-region substrate (`StrengthLoadEngine.perRegion`) handles strength but nothing attributes endurance/conditioning load to a region. That attribution + the anchor/saturating modifier is the build.

Per CONTEXT.md (locked: "Cross-modal is the one new engine") and `v2-crossmodal-and-measurement.md` §1.3: a NEW pure struct with static methods, reusing the existing models. Direction is HIGH-confidence (interference-effect literature); MAGNITUDE is an honest, shadow-tuned heuristic — label it as such, never over-claim precision, never say "injury prediction".

This plan builds the engine DARK as a pure struct only. It does NOT wire it into any pipeline, surface, or shadow log — that is Plan 03 (the shadow-validation gate). Nothing here drives any user-facing number.

Purpose: the cross-modal channel the Phase 43 verdict will consume once shadow-validated.
Output: `CrossModalFatigueEngine.swift` + a full unit-test suite proving the run-hits-squat-not-bench behaviour and the anti-linear-stacking property.

TDD: this is pure I/O-defined logic (input sessions + planned exercise region -> per-region carry + per-exercise adjustment). Write the failing tests first, then the engine.

Assert `regionPenalty(E_large) < 2 * regionPenalty(E_large/2)` style concavity and `regionPenalty <= maxPenalty`.

- Test (determinism): same inputs -> identical outputs to 1e-12 across two calls.

Doc comment: this is the directional cross-modal carry (run -> legs, spares chest); DIRECTION is high-confidence (interference-effect meta-analyses), MAGNITUDE is an honest shadow-tuned heuristic to be calibrated, NEVER an injury prediction.

Structure (per `v2-crossmodal-and-measurement.md` §1.3, steps 1-4):

1. `enum Constants` (the single home for tunables, mirroring StrengthLoadEngine.Constants): per-sportType region beta coefficients (running -> legs ~1.0; cycling -> legs ~0.7; rowing/ski via crossfit-or-custom -> legs ~0.6 + back ~0.5; swimming -> back/shoulders ~0.6; teamSport/crossfit mixed -> a default fullBody-distributed profile), per-region decay tau (`tauLegs` ~2.0d, `tauUpper` ~1.5d), `k` (saturation rate), `maxPenalty` (cap, e.g. 0.10 so the worst leg case is ~ -10%), the systemic floor (`systemicMin` ~0.85), and REUSE `StrengthLoadEngine.Constants.elevationDeadband` for the personal-normal deadband. Document every constant as a heuristic prior.

2. `regionCarry(sessions:asOf:calendar:window:) -> [MuscleRegion: Double]`: for each non-strength session in the window, `srpeLoad = WorkloadCalculator.srpeLoad(durationSeconds:sessionRPE:)` (skip when `sessionRPE == nil`), distribute by the sportType beta map, multiply by `decay(Δdays)=exp(-Δdays/tau_region)`, sum per region. Add the existing strength per-region load from `StrengthLoadEngine.perMuscleStrengthLoad(...).perRegion` over the same window so a heavy squat day also contributes leg carry. (Acute window.)

3. `regionElevation`: normalize acute regionCarry against the athlete's own chronic regional carry using the SAME deadband+saturating shape as `StrengthLoadEngine.perMuscleElevation(acute:chronic:)` -> per-region elevation `E_r` in 0...1. Above-personal-normal only.

4. `regionPenalty(_ E: Double) -> Double = maxPenalty * (1 - exp(-k * E))` — the concave saturating anchor+modifier (anti-linear-stacking by construction; bounded by maxPenalty).

5. `exerciseAdjustment(forRegion:systemicReadiness:regionElevations:) -> Double = systemicFactor * (1 - regionPenalty(E_region))` where `systemicFactor` maps systemic readiness 0...100 into `[systemicMin, 1.0]` (100 -> 1.0; low -> systemicMin). For `fullBody` planned exercises, use the max region elevation (or a documented aggregate). Return a per-exercise multiplicative factor in (0, 1].

6. A top-level `CrossModalResult` struct (Equatable): `perRegionCarry`, `perRegionElevation`, and a helper to compute `exerciseAdjustment(forRegion:)` plus a one-line `dominantReason` string ("legs still loaded from yesterday's run") assembled from the dominant contributing region+source session — glass-box, decomposable to (region, source session, days-ago, elevation), Tuwa-only, never "injury prediction". The reason string is built but NOT surfaced this phase.

Do NOT modify `StrengthLoadEngine`, `StrainRiskEngine`, `FatigueIndexEngine`, or any pipeline. Do NOT add the engine to any shadow arm here (Plan 03).
