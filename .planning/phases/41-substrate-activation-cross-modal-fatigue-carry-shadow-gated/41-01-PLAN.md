<objective>
Activate the dormant PRS readiness/strain pipeline so it runs in PRODUCTION on the verdict-feeding dashboard surface (no longer tests-only), and close the deferred Phase-28 dual-run UI review. This is ACT-01.

The pipeline is built, tested green, and wired — but switched off: `PRSActivation.isEnabled` defaults `false`, so `ReadinessFusionEngine.compute` / `StrainRiskEngine.fuse` / `AutoregulationEngine.recommendReadiness` are called in unit tests ONLY, never in any production file (verified in `PRSReadinessInputBuilder` doc comment and `DashboardViewModel.buildDualRunMessage`). The live recovery score is still the flat 7-day mean; the live recommendation is still the legacy `(recovery x ACWR)` matrix.

Per CONTEXT.md (locked: "Activate, do not rebuild") and research §202, do NOT flip the app-wide `PRSActivation` / `PRSMasterActivation` defaults (existing `AutoregulationFlagFenceTests` + `BaselineTierFenceTests` golden snapshots enforce byte-identical legacy behaviour and MUST stay green). Instead introduce a SURFACE-SCOPED activation that un-gates the readiness/strain compute on the verdict-feeding dashboard surface only, leaving the legacy recovery score live everywhere else.

ACTIVATION MECHANISM (revised — Option A, lowest-risk, preserves the flag-off fence tests literally unchanged): the surface flag `VerdictSurfaceActivation.isEnabled` DEFAULTS FALSE. The verdict-feeding surface goes live because the PRODUCTION dashboard path explicitly opts in: after `DashboardViewModel.load(...)` finishes, the View calls a new synchronous `viewModel.activateVerdictSurface()` that runs the gated dual-run build inside `VerdictSurfaceActivation.withEnabled(true) { ... }`. This makes the surface ACTIVE in the real app while keeping the default-off semantics that the three flag-off fence tests rely on (those tests make BARE calls with no override and expect nil/no-op). We deliberately do NOT make the surface flag default `true` and do NOT rely on any "default-true OR-guard", because doing so would make the bare-call fence tests return non-nil and break them — falsifying SC5 (byte-identical legacy behaviour, fences green) and this plan's own must_haves.

Why this still satisfies ACT-01: the surface is activated for the production path (the engines run live on the dashboard), the runtime flag-gate is effectively REMOVED for that surface (the production code opts in unconditionally — there is no user-facing kill switch left in the production path for this surface), and honest-confidence deferral is preserved (cold-start => `PRSReadinessInputBuilder.build` returns nil => no fabricated verdict).

Purpose: this is the foundation the Phase 43 verdict consumes — the verdict's readiness/strain channels must be computed by live production code, not test-only code.
Output: a surface-scoped activation flag (default false), the production dashboard path explicitly opting that surface in via `withEnabled(true)`, the dashboard surface running the live PRS engines with honest-confidence deferral preserved, the Phase-28 dual-run card reviewed against DESIGN.md + naming guards.

SCOPE FENCE (from CONTEXT.md): NO new suggest-and-confirm verdict CARD, NO plan-input, NO measurement here. The existing dashboard readiness/strain dual-run display is the acceptable surface for ACT-01.
