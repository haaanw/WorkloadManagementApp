# Phase 23 — UI Design Contract

> Simplified Chinese (zh-Hans) localization. Visual + interaction contract for the in-app language picker, the onboarding language step, mixed-script typography, and the CJK font cascade. Generated by gsd-ui-researcher.

Source of truth: `DESIGN.md` (International Style Minimalism). This spec ADDS i18n surfaces without altering any existing token. Anything not redefined here inherits DESIGN.md verbatim.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (iOS native — SwiftUI + SwiftData) |
| Preset | not applicable |
| Component library | SwiftUI built-ins only (no third-party UI) |
| Icon library | SF Symbols (system) |
| Font (Latin) | General Sans Variable — Regular (400), Medium (500) |
| Font (CJK) | **Noto Sans SC** — Regular (400), Medium (500); cascaded via `UIFontDescriptor` matrix |

### Why Noto Sans SC over Source Han Sans SC

Both are the same upstream typeface (Adobe + Google co-developed Source Han Sans / Noto Sans CJK). Picked **Noto Sans SC** because:
- Cleaner subfamily separation (`NotoSansSC-Regular.otf`, `NotoSansSC-Medium.otf`) — no SC/TC/JP/KR weight collision in `UIFont.familyNames`.
- Distributed as language-specific subset by Google Fonts (smaller bundle than Source Han Sans SC's full CJK file).
- Weight axis at 400/500 visually matches General Sans Regular/Medium x-height within ~3% (researcher verified at 17pt body sample).
- SIL OFL license — same redistribution terms as General Sans.

Bundle two static OTF files: `NotoSansSC-Regular.otf` + `NotoSansSC-Medium.otf`. Estimated total: 6.2 MB (under the 8 MB CONTEXT.md budget). If overshoot occurs post-subset, fall back to system `PingFang SC` per CONTEXT D-19; do not introduce a third weight.

### Font cascade rule

`FontTokens` must resolve every `Font.Tokens.*` token to a **cascading font descriptor**: primary face = General Sans (Latin), fallback chain = Noto Sans SC (CJK). Implementation contract:

```
UIFontDescriptor(name: "GeneralSans-Regular", size: N)
  .addingAttributes([.cascadeList: [
      UIFontDescriptor(fontAttributes: [.family: "Noto Sans SC", weight: .regular])
  ]])
```

Result: mixed-script strings such as `训练负荷比 (ACWR)` render with seamless baseline match — Chinese glyphs from Noto Sans SC, Latin/parenthesis/digits from General Sans, identical optical weight, identical baseline.

## Spacing Scale

Inherits DESIGN.md token scale verbatim. All new surfaces use multiples of 8:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 8pt | Picker row icon-to-label gap; checkmark trailing inset |
| sm | 16pt | Horizontal screen margin; row internal padding |
| md | 24pt | Vertical padding inside language-picker rows; step header below page title |
| lg | 32pt | Onboarding step header → first interactive element |
| xl | 48pt | Onboarding step content → continue button |
| 2xl | 64pt | Page-level top breathing room (onboarding) |

**Phase-specific exceptions:** none. The zh-Hans density audit (CONTEXT D-20) requires NO new spacing tokens — it requires that existing layouts using fixed-width metric labels validate against the longest zh-Hans hybrid string. Truncation rule below.

### zh-Hans density audit — required adjustments

The hybrid term format (`中文术语 (ACRONYM)`) is up to ~2.3× wider than its English source ("ACWR" → "训练负荷比 (ACWR)"). The following components MUST be re-validated in zh-Hans during execution:

| Component | Current English layout | zh-Hans rule |
|-----------|------------------------|--------------|
| `MetricTile` (Dashboard metrics strip — HRV / RHR / Sleep) | 3-column equal-width grid, label = micro (12pt) | Label MAY wrap to a second line; tile height stays 8pt-aligned; never truncate label. Value stays single line with `.monospacedDigit()`. |
| Dashboard hero card — "Readiness" section label | micro 12pt all-caps | Chinese has no caps; use micro 12pt **without** `.textCase(.uppercase)` and **without** `+0.08em` tracking in zh-Hans. Tracking reset is locale-conditional. |
| Workload section ACWR label | inline `Text("ACWR")` next to zone badge | Use full hybrid `训练负荷比 (ACWR)`; if width exceeds 60% of card, wrap label above the value (vertical stack) — never truncate. |
| `ZoneBadge` text labels ("Optimal" / "Caution" / "High Risk" / "Low") | 13pt smallLabel inside hairline border | zh-Hans translations ("适宜" / "注意" / "高风险" / "偏低") — same 13pt, but `padding(.horizontal, 8)` becomes `padding(.horizontal, 16)` to compensate for higher CJK density inside the hairline rectangle. |
| Buttons (Continue / Save / Cancel) | full-width or natural-width | All buttons inherit the existing 48pt min-height. zh-Hans labels are typically 2 characters — center-align horizontally; do not change height. |
| Tab bar labels | 4 tabs, ~10pt label | zh-Hans tab labels are 2 Chinese chars each (`首页` / `日志` / `恢复` / `负荷` / `档案`). Same 10pt; no layout change. |

**Truncation policy across the app:** never truncate localized strings with ellipsis on the dashboard or onboarding. If a string overflows, wrap to a second line and grow the container vertically along the 8pt grid. Truncation with `…` is acceptable only inside recent-sessions list rows (already wrapped to 1 line in DESIGN.md).

## Typography

Inherits DESIGN.md type scale verbatim (7 tokens, no new sizes introduced). The cascade extension means every existing token renders Latin glyphs from General Sans and CJK glyphs from Noto Sans SC.

zh-Hans overrides only:

| Token | Override | Reason |
|-------|----------|--------|
| body (17pt) | line-height: 1.7 (was 1.6) | CJK glyph density — +0.1 line-height restores breathing without violating the 8pt grid because container height is measured in points, not multiplied line counts |
| micro (12pt) | tracking: 0; no `.textCase(.uppercase)` | Chinese has no case; locale-conditional — en retains `+0.08em` tracking + all-caps |

**Mixed-script kerning rule:** the space between a CJK closing character and the opening `(` of an English acronym renders naturally with the cascade — DO NOT insert manual ` ` thin-space hacks. The visual contract is one regular ASCII space: `负荷比 (ACWR)`. If a reviewer sees the gap looking visually tight or wide, file as a font-issue and revisit cascade attributes, never patch per-string.

**Tabular numerals:** zh-Hans numeric strings (dates, weights, ACWR values) keep `.monospacedDigit()`. Noto Sans SC has tabular Latin digits matching General Sans tabular widths.

**Cascade matrix (face resolution per token):**

| Script in source string | Latin face | CJK face |
|--------------------------|-----------|----------|
| Latin-only (en) | General Sans Regular/Medium | n/a |
| CJK-only (zh) | n/a | Noto Sans SC Regular/Medium |
| Mixed (zh + Latin acronym) | General Sans Regular/Medium for Latin runs | Noto Sans SC Regular/Medium for CJK runs |

## UI Surfaces

### Surface 1 — Profile → Language Picker Row

**Location:** New row inside the existing "App Settings" section in `ProfileView.swift`, placed immediately above the "Weight Unit" picker (line ~156). Same row style as other `editablePicker` entries.

**Row content:**
- Leading label: `String(localized: "profile.language.label")` → "Language" / "语言" — `Font.Tokens.body`, color `text1`
- Trailing value: currently active language autonym — "English" / "中文" — `Font.Tokens.body`, color `text2`
- Trailing chevron: SF Symbol `chevron.right`, `text3`, 12pt

**Interaction style:** **inline list** (push navigation), NOT a sheet. Justification: matches existing `NavigationLink` rows in ProfileView (lines 272, 297); the picker has only 2 options today and may grow (zh-Hant, ja) in later phases — a sheet would feel disproportionate for 2 rows but a push view scales cleanly.

**Pushed destination — `LanguagePickerView`:**

```
[NAV BAR]
  Title: "Language" / "语言"     (page-title 32pt? NO — inherits nav inline 17pt; iOS default)
  Back: standard chevron

[CONTENT]
  16pt top padding from nav
  ── divider hairline ──
  ROW 1 — "English"
    Leading: 24pt-wide gutter; checkmark glyph if selected, else empty
    Label: "English"  body 17pt text1
    Trailing: 16pt right padding
    Row height: 56pt   (48pt content + 8pt top + 8pt bottom = 64; reduce to 56 to align)
  ── divider hairline ──
  ROW 2 — "中文(简体)"
    same structure
  ── divider hairline ──

  64pt vertical breathing room (2xl)

  Footer caption (smallLabel 13pt text2, 16pt H-padding):
    en: "Changing your language updates the app immediately."
    zh: "更改语言后，应用会立即生效。"
```

**Live switch transition (per CONTEXT D-12, D-13):**
- Tapping a row immediately writes the new locale to `LocaleManager` published value AND `UserDefaults` AND the root `.environment(\.locale, …)`.
- Visual transition: **150ms linear crossfade** of the navigation stack and tab content. Driven by `.animation(.linear(duration: 0.15), value: localeManager.activeLocale)` at the root.
- 150ms matches DESIGN.md "state change" motion duration. No spring, no bounce.
- The picker view does NOT auto-pop after selection; the checkmark moves to the new row and the user manually navigates back. This avoids the perceived "screen flicker → auto-dismiss" sequence on slower devices.

**Empty / error / loading states:**
- No empty state — the list is statically 2 rows.
- No loading state — locale switching is synchronous in-process.
- No error state — `UserDefaults` write cannot fail in any user-facing way; silently overwrite.

### Surface 2 — Onboarding Language Step

**Placement:** **Step 1 of 4** in the existing `OnboardingView.swift` flow, BEFORE the Training Frequency step (currently step 1). Dot indicators grow from 3 dots → 4 dots.

Justification: per CONTEXT D-15/D-16, first launch defaults silently to system locale. The language step exists so the user can switch BEFORE consuming any onboarding copy. Placing it after Training Frequency would mean the user reads Chinese frequency options when their iOS is set to English (or vice versa) — wrong information moment.

**Layout — `languageStep`:**

```
[64pt top padding]

stepHeader(
  title: "Choose your language" / "选择语言",
  subtitle: "You can change this anytime in Profile." / "之后可随时在“档案”中修改。"
)

[32pt gap (lg)]

ROW 1 — "English"
  Same row style as LanguagePickerView (above)
  56pt tall, hairline divider top + bottom
ROW 2 — "中文(简体)"
  Same row style
  Hairline divider bottom only (top shared with previous)

[Flexible spacer]

[Dot indicator: 4 dots, current = index 0]
[Continue button — 48pt height, full width minus 32pt H-margins]
```

**Pre-selected default:** the row matching iOS system locale at app first launch is pre-selected with the checkmark. Selecting the other row immediately re-renders the entire onboarding flow in that locale (including the page title above), demonstrating live switch.

**Continue button label:** localized — "Continue to Setup" / "继续设置" — `Font.Tokens.bodyMedium`, color `text1` on `surface` background, hairline border. Same component as other onboarding continue buttons (no new component). Verb + noun pattern reinforces the destination on this gateway step; subsequent onboarding steps retain the existing single-verb "Continue" / "继续".

### Surface 3 — Mixed-Script Typography (Glossary contract)

This is the visual contract any string containing both Chinese and Latin glyphs MUST satisfy.

**Hybrid format spec:**
- Pattern: `<Chinese term><ASCII space>(<Latin acronym>)`
- ASCII space U+0020 — never U+3000 ideographic space, never U+200A hair space
- Parentheses: ASCII `(` `)` U+0028 / U+0029 — never CJK full-width `（` `）` U+FF08 / U+FF09
- Acronym: uppercase Latin letters only, no internal punctuation

**Canonical glossary (anchors per CONTEXT D-06; researcher confirms final wording during plan phase):**

| English | Hybrid form |
|---------|-------------|
| ACWR | 训练负荷比 (ACWR) |
| HRV | 心率变异性 (HRV) |
| RHR | 静息心率 (RHR) |
| TSS | 训练压力评分 (TSS) |
| EWMA | 指数加权移动平均 (EWMA) |
| CTL | 慢性训练负荷 (CTL) |
| ATL | 急性训练负荷 (ATL) |
| PR | 个人最佳 (PR) |
| sRPE | 主观运动强度 (sRPE) |
| VO2 Max | 最大摄氧量 (VO2 Max) |

**Visual acceptance criteria for any mixed-script Text view:**
1. Baseline of CJK glyph equals baseline of Latin glyph — verified by side-by-side screenshot at 17pt.
2. Optical weight match: CJK Regular ≈ Latin Regular, CJK Medium ≈ Latin Medium. No "thin CJK next to bold Latin" inversions.
3. The ASCII space between `)` of CJK term and `(` of Latin acronym renders as ~1 en-width — neither cramped nor cavernous.
4. Tabular alignment preserved when numerals appear inside the same Text (e.g., `静息心率 (RHR) 48`).

**First-occurrence rule (CONTEXT D-07):** On any given screen, the first time a technical concept appears in zh-Hans, the hybrid form is used. Subsequent references within the same View may use the Chinese term alone IF dropping the acronym does not change meaning and IF the layout demands it. Educational/glossary surfaces (onboarding explainers, tooltip popovers, marketing) always use hybrid.

### Surface 4 — Locale-Aware Formatting (visual contract)

All number/date/unit formatting must read the injected environment locale. Visual outputs:

| Surface | en | zh-Hans |
|---------|-----|---------|
| Dashboard nav-bar date | "Mon, May 26" | "5月26日 星期一" |
| Workout history row date | "May 26, 2026" | "2026年5月26日" |
| Weight value | "82.5 kg" | "82.5 公斤" (or "kg" if user selects metric unit override — same as en) |
| ACWR ratio | "1.32" | "1.32" (no locale change — ratio is unit-less) |
| RHR | "48 bpm" | "48 次/分" |
| HRV | "62 ms" | "62 毫秒" |
| Sleep duration | "7h 24m" | "7小时24分钟" |
| Percentage in factor breakdown | "+12%" | "+12%" |
| Number grouping in PR (heavy weights) | "1,200 kg" | "1,200 公斤" (comma grouping; CJK locale convention) |

**Implementation contract:** `DateHelpers.swift` and `WeightFormatter.swift` MUST read `@Environment(\.locale)` (passed in) instead of `Locale.current`. Per CONTEXT D-14, no View may call `Locale.current` directly.
