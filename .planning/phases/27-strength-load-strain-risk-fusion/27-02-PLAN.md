<objective>
Build the pure `LoadDistributionEngine` (static methods): construct a unified daily-load
series (sRPE/TRIMP endurance + strength hard-set load), compute Foster monotony & strain,
and **completeness-gate** them — returning `nil` (with an explicit fallback signal) when
there is not enough logged daily load, in which case a streak / session-density /
load-spike heuristic is used instead (moat-design §2.6 + codex MAJOR finding).

Purpose: monotony/strain is the one new evidence-supported load-distribution primitive,
but it is fragile on sparse consumer logs — this wave makes it honest and gated. Wave 3's
`StrainRiskEngine` consumes the gated result + fallback flag.

Output: `LoadDistributionEngine.swift` + tests.
</objective>
