<objective>
Wire the same-phase baseline algorithm (Plan 01) into the live recovery flow. `RecoveryPipeline.run()` gains an optional `CycleTrackingService`, queries it for `CycleContext`, joins historical `RecoverySnapshot` HRV/RHR with the `CyclePhase` active on each date (read-time join via `MenstrualCycleSnapshot`), buckets those readings, and — only when the confidence gate passes and the current bucket meets the 4-reading minimum — feeds same-phase baselines into the engine. Otherwise the existing 7-day path runs unchanged.

Purpose: Deliver CYCLE-05 (pipeline integration + graceful degradation) and complete CYCLE-04 in the live app. The gate enforces the locked decisions: D-04 (confidence >= 0.7 AND no exclusion AND phase != .unknown), D-05 (OC always 7-day, via hasExclusion), D-06 (per-bucket fallback — the engine's `??` from Plan 01 handles this since we only populate same-phase fields for buckets that qualify), D-07 (hard switch). The non-breaking scope lock is preserved by making `CycleTrackingService` an optional parameter defaulting to nil — when absent, run() is byte-identical to today.

Output: New `CycleSnapshotRepository` (date-windowed MenstrualCycleSnapshot reads), extended `RecoveryRepository` history window, gated derivation in `RecoveryPipeline.run`, `CycleTrackingService` added to `AppContainer`, and both ViewModels passing it through. Build verified; .pbxproj updated for the new repository file.
</objective>
