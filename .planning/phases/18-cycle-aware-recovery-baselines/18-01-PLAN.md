<objective>
Extend the pure `RecoveryScoreEngine` struct so HRV and RHR recovery components can score against a confidence-gated **same-phase** baseline (the athlete's own same-bucket history) instead of the male-normative 7-day rolling baseline — while behaving identically when no same-phase data is supplied.

This plan is engine-only: pure Swift, no HealthKit, no SwiftData, no `CycleContext` orchestration. It defines the algorithm and its contracts (bucket mapping, same-phase baseline computation, the 4-reading minimum, and how `compute()` selects which baseline feeds the existing `ratioToScore` math). All gating and data joins happen in Plan 02, which calls into the contracts defined here.

Purpose: The same-phase baseline removes predictable within-athlete cyclic variance (luteal HRV suppression / RHR rise) so normal luteal physiology stops reading as "declining recovery", while genuine deviations from the athlete's own luteal norm still trigger fatigue. This is the heart of CYCLE-04 and the most testable, deterministic part of the phase.

Output: Modified `RecoveryScoreEngine.swift` (bucket helper, same-phase baseline function, `RecoveryInput` extension, baseline selection in `compute()`) plus comprehensive unit tests covering both ROADMAP worked examples, the identical-behavior regression, and the per-bucket 4-reading minimum.
</objective>
