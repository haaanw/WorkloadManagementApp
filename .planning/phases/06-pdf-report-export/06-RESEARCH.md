# Phase 6: PDF Report Export - Research

**Researched:** 2026-04-25
**Domain:** PDF generation with UIGraphicsPDFRenderer, Core Graphics drawing, SwiftUI integration
**Confidence:** HIGH

## Summary

This phase adds PDF report generation to the Tonus iOS app using Apple's native `UIGraphicsPDFRenderer` API with Core Graphics drawing primitives. No new SPM dependencies are needed. The architecture follows the existing pure-struct engine pattern established by `CSVExportEngine` -- a new `PDFReportEngine` struct with static methods handles all rendering. The existing `ShareSheet`, `SubscriptionService` gating, and `WorkloadView` export flow provide ready integration points.

Two distinct PDF documents are produced: (1) an athlete training report with recovery trends, workload charts, session log, and PR table, and (2) a coach roster summary table. Both use Core Graphics `CGContext` drawing within `UIGraphicsPDFRenderer.pdfData(actions:)`, with DM Sans fonts loaded via `UIFont(name:size:)` and rendered as `NSAttributedString.draw(in:)` calls.

**Primary recommendation:** Build `PDFReportEngine` as a pure struct with two public static methods -- `generateAthleteReport(...)` and `generateCoachRosterReport(...)` -- each returning `Data`. Charts are drawn as `CGPath` line segments directly on the PDF context. Page breaks are managed by tracking a running Y cursor and calling `context.beginPage()` when content exceeds the usable area.

### Pattern 2: Y-Cursor Page Management
**What:** Track a running `cursorY` value. Before drawing any section, check if remaining page space is sufficient. If not, draw footer on current page, call `context.beginPage()`, draw header on new page, reset cursor.
**When to use:** Every section draw call checks available space.
**Example:**
```swift
// Source: standard UIGraphicsPDFRenderer pattern [CITED: hackingwithswift.com]
var cursorY: CGFloat = marginV + headerHeight + 16  // after header

func ensureSpace(_ needed: CGFloat, context: UIGraphicsPDFRendererContext, pageNumber: inout Int) {
    let available = pageHeight - marginV - footerHeight - cursorY
    if needed > available {
        drawFooter(context: context.cgContext, pageNumber: pageNumber)
        pageNumber += 1
        context.beginPage()
        drawHeader(context: context.cgContext, ...)
        cursorY = marginV + headerHeight + 16
    }
}
```

### Pattern 3: Core Graphics Chart Drawing
**What:** Draw trend line charts using `CGContext.move(to:)` and `CGContext.addLine(to:)` with `CGPath`. Map data points to pixel coordinates within a defined chart rect.
**When to use:** Recovery score trend (single line) and workload trends (ATL + CTL dual line).
**Example:**
```swift
// Source: Core Graphics standard API [VERIFIED: Apple documentation]
static func drawLineChart(
    context: CGContext,
    rect: CGRect,
    dataPoints: [(date: Date, value: Double)],
    strokeColor: CGColor,
    lineWidth: CGFloat = 1.5
) {
    guard dataPoints.count >= 2 else { return }
    let minVal = dataPoints.map(\.value).min() ?? 0
    let maxVal = dataPoints.map(\.value).max() ?? 100
    let range = max(maxVal - minVal, 1)

    context.setStrokeColor(strokeColor)
    context.setLineWidth(lineWidth)

    for (i, point) in dataPoints.enumerated() {
        let x = rect.minX + (CGFloat(i) / CGFloat(dataPoints.count - 1)) * rect.width
        let y = rect.maxY - ((CGFloat(point.value - minVal) / CGFloat(range)) * rect.height)
        if i == 0 {
            context.move(to: CGPoint(x: x, y: y))
        } else {
            context.addLine(to: CGPoint(x: x, y: y))
        }
    }
    context.strokePath()
}
```

### Pattern 4: Text Drawing with NSAttributedString
**What:** Use `NSAttributedString` with `UIFont` and `NSParagraphStyle` attributes, then call `.draw(in: CGRect)` to render text within the PDF context.
**When to use:** All text in the PDF document.
**Example:**
```swift
// Source: NSAttributedString.draw(in:) [VERIFIED: Apple Foundation API]
static func drawText(
    _ text: String,
    in rect: CGRect,
    font: UIFont,
    color: UIColor,
    alignment: NSTextAlignment = .left
) {
    let paragraphStyle = NSMutableParagraphStyle()
    paragraphStyle.alignment = alignment
    let attributes: [NSAttributedString.Key: Any] = [
        .font: font,
        .foregroundColor: color,
        .paragraphStyle: paragraphStyle
    ]
    (text as NSString).draw(in: rect, withAttributes: attributes)
}
```

### Anti-Patterns to Avoid
- **Using SwiftUI Font in PDF context:** SwiftUI `Font` cannot be used with Core Graphics. Must use `UIFont(name: "DMSans-Regular", size:)` for all PDF text rendering. [VERIFIED: codebase already validates UIFont availability in WorkloadApp.swift]
- **Rendering SwiftUI Charts to image for PDF:** Loses vector quality, adds rasterization complexity, and requires offscreen rendering on main thread. Draw charts manually with CGContext instead.
- **Async PDF generation without progress indication:** PDF generation with chart drawing may take 100-500ms. Show loading state ("Generating...") to avoid appearing frozen.
- **Including raw HealthKit data:** Per D-04 and Apple guidelines, only composite scores (recoveryScore, sleepScore) appear in the PDF. Never include raw HRV SDNN, raw RHR, or raw sleep duration values.

## Common Pitfalls

### Pitfall 1: Font Name Mismatch Between SwiftUI and UIKit
**What goes wrong:** DM Sans font files are registered as `.ttf` but referenced with the PostScript name. The UIFont name might differ from the filename.
**Why it happens:** Font names in iOS are PostScript names, not filenames. `DMSans-Regular.ttf` registers as `"DMSans-Regular"` but this depends on the font's internal metadata.
**How to avoid:** The codebase already validates font availability at launch: `UIFont(name: "DMSans-Regular", size: 15) != nil` in WorkloadApp.swift. Use the same names for PDF: `UIFont(name: "DMSans-Regular", size:)` and `UIFont(name: "DMSans-Medium", size:)`. [VERIFIED: WorkloadApp.swift lines 12-17]
**Warning signs:** Text renders in system font instead of DM Sans; assertion fires in debug.

### Pitfall 2: Page Break Mid-Table-Row
**What goes wrong:** A session log table row gets split across two pages, with half a row at the bottom of one page and the other half at the top of the next.
**Why it happens:** Not checking remaining space before each row.
**How to avoid:** Before drawing each table row, check `cursorY + rowHeight > pageHeight - marginV - footerHeight`. If so, draw footer, begin new page with header + table column header repeated.
**Warning signs:** Clipped text at page bottom, orphaned row fragments.

### Pitfall 3: Empty Data Sections
**What goes wrong:** PDF crashes or renders blank sections when athlete has no sessions, no recovery data, or no PRs in the selected period.
**Why it happens:** Chart drawing assumes >= 2 data points; table drawing assumes >= 1 row.
**How to avoid:** Guard each section: if data is empty, render the "no data" message (e.g., "No personal records achieved in this period.") per the UI-SPEC copywriting contract. Charts need >= 2 points; show text fallback otherwise.
**Warning signs:** Empty white space where a section should be, or crash on empty array access.

### Pitfall 4: Coach Report Missing Athlete Data
**What goes wrong:** Coach generates roster report but some athletes show blank recovery/workload data.
**Why it happens:** Linked athlete data may not have synced yet (Supabase pull is async), or athlete never logged sessions.
**How to avoid:** Use optional handling: display "--" for missing recovery score, "No data" for missing zone. The CoachRosterViewModel already handles this with optional dictionaries `latestWorkloadSnapshot[id]` and `latestRecoverySnapshot[id]`. [VERIFIED: CoachRosterViewModel.swift]
**Warning signs:** Nil force-unwrap crashes, blank cells in roster table.

### Pitfall 5: Large Session Log Exceeding Memory
**What goes wrong:** Athlete with 12 weeks of daily sessions could have 84+ rows in the session log table, producing many pages.
**Why it happens:** 12-week range with high training frequency.
**How to avoid:** UIGraphicsPDFRenderer handles memory efficiently since it streams pages. The Y-cursor pattern with page breaks handles multi-page tables naturally. No special memory management needed, but test with 50+ session datasets.
**Warning signs:** Slow generation time (> 1s), which should trigger loading indicator.

### Pitfall 6: Color Mode in PDF
**What goes wrong:** PDF uses dark mode colors making text invisible on white paper.
**Why it happens:** Using ColorTokens (which adapt to system color scheme) instead of fixed print-ready colors.
**How to avoid:** PDF must use hardcoded light-mode-derived colors as specified in the UI-SPEC: `#1C1915` for text, `#CFCBC5` for dividers, `#FFFFFF` for page background. Never reference ColorTokens in PDF drawing code. [VERIFIED: 06-UI-SPEC.md PDF Document Color section]
**Warning signs:** Dark background in PDF, light text on white paper.

### UIGraphicsPDFRenderer Basic Usage
```swift
// Source: UIGraphicsPDFRenderer Apple API [VERIFIED: Apple documentation]
let pageRect = CGRect(x: 0, y: 0, width: 612, height: 792)
let renderer = UIGraphicsPDFRenderer(bounds: pageRect)

let data = renderer.pdfData { context in
    context.beginPage()

    let cgContext = context.cgContext

    // Draw text
    let title = "Training Report"
    let font = UIFont(name: "DMSans-Medium", size: 24)!
    let attributes: [NSAttributedString.Key: Any] = [
        .font: font,
        .foregroundColor: UIColor(red: 0.11, green: 0.10, blue: 0.08, alpha: 1) // #1C1915
    ]
    (title as NSString).draw(
        in: CGRect(x: 48, y: 64, width: 516, height: 30),
        withAttributes: attributes
    )

    // Draw hairline rule
    cgContext.setStrokeColor(UIColor(red: 0.81, green: 0.80, blue: 0.77, alpha: 1).cgColor) // #CFCBC5
    cgContext.setLineWidth(0.5)
    cgContext.move(to: CGPoint(x: 48, y: 120))
    cgContext.addLine(to: CGPoint(x: 564, y: 120))
    cgContext.strokePath()
}

// Write to temp file
let url = FileManager.default.temporaryDirectory.appendingPathComponent("report.pdf")
try data.write(to: url)
```

### Table Drawing Pattern
```swift
// Source: Core Graphics table drawing [ASSUMED — standard CG pattern]
static func drawTableRow(
    context: CGContext,
    columns: [(text: String, width: CGFloat)],
    y: CGFloat,
    font: UIFont,
    color: UIColor,
    rowHeight: CGFloat = 24
) {
    var x: CGFloat = 48 // left margin
    for (text, width) in columns {
        let attributes: [NSAttributedString.Key: Any] = [
            .font: font,
            .foregroundColor: color
        ]
        let textRect = CGRect(x: x + 4, y: y + 4, width: width - 8, height: rowHeight - 8)
        (text as NSString).draw(in: textRect, withAttributes: attributes)
        x += width
    }

    // Bottom border
    context.setStrokeColor(UIColor(red: 0.81, green: 0.80, blue: 0.77, alpha: 1).cgColor)
    context.setLineWidth(0.5)
    context.move(to: CGPoint(x: 48, y: y + rowHeight))
    context.addLine(to: CGPoint(x: 564, y: y + rowHeight))
    context.strokePath()
}
```

## Open Questions

1. **Coach data freshness for roster report**
   - What we know: CoachRosterViewModel fetches latest snapshots from SwiftData. Sync pulls athlete data on app foreground.
   - What's unclear: If sync hasn't run recently, roster report may show stale data. Should we force a sync before generating?
   - Recommendation: Do NOT force sync -- it adds async complexity and network dependency to a generation flow. Use whatever data is locally available. The "Generated by Tonus" footer with date provides staleness context.

2. **Text measurement for dynamic row heights**
   - What we know: Session names and exercise names can vary in length. Fixed 24pt row height may truncate long names.
   - What's unclear: Whether any exercise names exceed single-line width at 13pt in the session log table.
   - Recommendation: Use `NSString.boundingRect(with:options:attributes:context:)` to measure text height and adjust row height dynamically. This is a minor implementation detail within Claude's discretion.
