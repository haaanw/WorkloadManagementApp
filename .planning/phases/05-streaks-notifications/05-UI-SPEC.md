## Screen-by-Screen Specifications

### 1. Dashboard -- Streak Row in WeeklySummaryCard

**Location:** First content row inside the expanded WeeklySummaryCard, above the SESSIONS/VOLUME row.

**Layout:**
```
[flame.fill icon 13pt]  8pt gap  [streak count -- sectionHead weight]  8pt gap  ["week streak" -- label, text2]
```

- Icon: SF Symbol `flame.fill`, 13pt, `ColorTokens.text2`
- Streak count: `Font.Tokens.sectionHead`, `ColorTokens.text1`, `.monospacedDigit()`
- Label text: `Font.Tokens.label`, `ColorTokens.text2`
- Entire row: `.padding(.horizontal, 16)`, `.padding(.bottom, 16)`
- Pluralization: "1 week streak" / "5 week streak"

**Visibility rules (D-02):**
- Streak >= 1: show the row
- Streak == 0: hide the row entirely (no "0 weeks", no CTA, no placeholder)

**Interaction:** None. Display only.

### 2. Dashboard -- Notification Pre-Permission Card (D-07)

**Format decision:** Inline card on the dashboard (matching WelcomeActionCard pattern), not a full-screen sheet. Rationale: the codebase uses inline cards for first-run prompts (WelcomeActionCard); a sheet would be a pattern break.

**Trigger:** First dashboard visit where notification authorization status is `.notDetermined`. Track via `@AppStorage("notificationPrePermissionShown")`.

**Position:** Below WeeklySummaryCard, above Recent Sessions. Same vertical slot as WelcomeActionCard (they are mutually exclusive -- WelcomeActionCard shows when no sessions exist; pre-permission card shows after sessions exist).

**Layout:**
```
[NOTIFICATIONS -- micro caps, text3, tracking 1.2]        16pt top padding
[Stay on track -- sectionHead, text1]                      0pt gap (4pt top via line-height)
[Get a weekly summary of your sessions,                    4pt top, 16pt bottom
 PRs, and streak every Sunday. -- label, text2]
[Enable Notifications] [Not Now]                           8pt gap between buttons, 16pt bottom/horizontal padding
```

**Card styling:**
- Background: `ColorTokens.surface`
- Border: `Rectangle().stroke(ColorTokens.divider, lineWidth: 0.5)`
- No rounded corners, no shadow

**Button styling (matches WelcomeActionCard):**
- "Enable Notifications": `Font.Tokens.label`, `ColorTokens.text1`, full-width in left half, `.overlay(Rectangle().stroke(ColorTokens.divider, lineWidth: 0.5))`, 8pt vertical padding
- "Not Now": same styling, right half

**Behavior:**
- "Enable Notifications" tapped: call `UNUserNotificationCenter.requestAuthorization(options: [.alert, .sound])`, then schedule default weekly notification. Set `@AppStorage` flag. Dismiss card.
- "Not Now" tapped: set `@AppStorage` flag. Dismiss card. User can enable later in Profile settings.

### 3. Profile -- Notification Settings (D-08)

**Placement decision:** New `NOTIFICATIONS` section in ProfileView, placed between PREFERENCES and CONNECTED DEVICES sections. Rationale: notification settings are distinct from athlete preferences (sport, weight unit) and warrant their own section header for scannability.

**Layout:**

```
--- sectionDivider ---
[NOTIFICATIONS -- sectionHeader()]

[Weekly Summary]                [Toggle on/off]       16pt horizontal, 16pt vertical padding
--- divider ---
[Day]                           [picker: Sunday]      16pt horizontal, 16pt vertical padding
--- divider ---
[Time]                          [picker: 7:00 PM]     16pt horizontal, 16pt vertical padding
--- sectionDivider ---
```

**Component patterns (match existing ProfileView):**

- Section header: `sectionHeader("NOTIFICATIONS")` -- reuses existing helper
- Toggle row: `HStack { Text("Weekly Summary").font(.Tokens.body).foregroundStyle(ColorTokens.text1); Spacer(); Toggle("", isOn: $notificationsEnabled).labelsHidden() }` -- matches Coach Only toggle pattern
- Day picker: `editablePicker("Day", ...)` with options Monday through Sunday -- reuses existing helper
- Time picker: custom time picker using `DatePicker` with `.datePickerStyle(.compact)` displaying hour/minute only, or an `editablePicker` with predefined time slots (every hour from 6 AM to 10 PM)

**Defaults (D-04):** Sunday, 7:00 PM

**State persistence:** `@AppStorage` for day and time preferences. NotificationService reads these to schedule `UNCalendarNotificationTrigger`.

**Disabled state:** When toggle is off, Day and Time rows appear with `ColorTokens.text3` text and are non-interactive (`.disabled(true)`).

### 4. Weekly Notification Content (D-06)

**Notification title:** "Your Week in Review"

**Notification body format (single string, max ~4 lines):**
```
{sessionCount} sessions logged{streakSuffix}. {prSuffix}{deltaSuffix}
```

**Examples:**
- "4 sessions logged -- 3 week streak. 2 new PRs! Volume up 12% from last week."
- "2 sessions logged. No new PRs. Volume down 8% from last week."
- "0 sessions this week. Log a session to keep your streak alive."

**Content rules:**
- Source data from `AnalyticsEngine.WeeklySummary` (sessions, PRs, deltas)
- Streak suffix: show " -- {N} week streak" only when streak >= 1
- PR suffix: show "{N} new PRs!" when > 0, "No new PRs." when 0
- Delta suffix: show "Volume {up/down} {N}% from last week." when delta != 0, omit when 0
- Zero-session special case: different copy to nudge re-engagement

**Notification category:** No actions required. Tapping opens the app to Dashboard.

## Interaction Contracts

| Interaction | Behavior |
|-------------|----------|
| Streak row tap | None -- display only |
| Pre-permission "Enable" tap | Request `UNUserNotificationCenter` authorization, schedule default notification, dismiss card |
| Pre-permission "Not Now" tap | Set `@AppStorage` flag, dismiss card, no system dialog |
| Profile toggle on | Schedule weekly notification with current day/time, request authorization if `.notDetermined` |
| Profile toggle off | Cancel all pending notification requests |
| Profile day/time change | Reschedule notification with new trigger |
| Notification tap | Open app to Dashboard (default behavior) |
