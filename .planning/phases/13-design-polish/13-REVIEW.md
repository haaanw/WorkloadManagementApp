# Phase 13: Code Review Report

**Reviewed:** 2026-05-10T12:00:00Z
**Depth:** standard
**Files Reviewed:** 21
**Status:** issues_found

## Summary

Phase 13 migrates the typeface from DM Sans to Alpino and introduces `SharpTextFieldStyle` as a 0pt-corner replacement for `.roundedBorder`. The new files (`FontTokens.swift`, `SharpTextFieldStyle.swift`, `FatigueAttentionBanner.swift`, `StalenessWarningBadge.swift`, `ToastBanner.swift`) are well-structured, follow the design system conventions, and are correctly registered in the Xcode project. Font files are bundled and registered in Info.plist.

Key concerns: a design system font violation in `UpgradeSheet.swift` (uses `.system()` instead of Alpino), a stale brand name in the PDF engine ("Tutrice" instead of "Faros"), and a `FontTokens` type scale that deviates from the sizes documented in DESIGN.md without the design document being updated to match.

## Critical Issues

### CR-01: PDFReportEngine uses stale brand name "Tutrice" instead of "Faros"

**File:** `WorkloadApp/Services/PDFReportEngine.swift:442,459`
**Issue:** The app was renamed to Faros (per project memory, 2026-05-10), but the PDF header and footer still reference "Tutrice". Every exported PDF will display the wrong product name.
**Fix:**
```swift
// Line 442
drawText("Faros", in: CGRect(x: marginH, y: marginV, width: 200, height: 24), font: fontMedium(15), color: textPrimary)

// Line 459
drawText("Generated by Faros", in: CGRect(x: marginH + 100, y: footerY + 4, width: contentWidth - 100, height: 20), font: fontRegular(11), color: textSecondary, alignment: .right)
```

## Warnings

### WR-01: UpgradeSheet uses `.system()` font instead of Alpino design tokens

**File:** `WorkloadApp/Views/Subscription/UpgradeSheet.swift:92`
**Issue:** The checkmark icon uses `.font(.system(size: 11, weight: .medium))` which renders in SF Pro, breaking the Alpino-only typography rule from DESIGN.md. This is in a high-visibility paywall screen.
**Fix:**
```swift
Image(systemName: "checkmark")
    .font(.Tokens.micro)
    .foregroundStyle(ColorTokens.text2)
    .frame(width: 16)
    .padding(.top, 2)
```

### WR-02: FontTokens type scale diverges from DESIGN.md without documentation

**File:** `WorkloadApp/Utilities/FontTokens.swift:13-41`
**Issue:** Every size in `FontTokens` is consistently larger than what DESIGN.md specifies: hero 64pt vs 56pt, pageTitle 32pt vs 28pt, sectionHead 19pt vs 17pt, body 17pt vs 15pt, label 15pt vs 13pt, micro 12pt vs 11pt. DESIGN.md line 25 allows 64pt "on larger devices" for the hero score, but the other sizes are undocumented. If this is intentional (e.g., better readability on device), DESIGN.md should be updated to reflect the actual implementation.
**Fix:** Update DESIGN.md type scale table to match the actual `FontTokens` values, or add a note explaining the +2pt device-specific bump.

### WR-03: UpgradeSheet subtitle references "Tutrice" brand

**File:** `WorkloadApp/Views/Subscription/UpgradeSheet.swift:336`
**Issue:** The `SubscriptionTier.subtitle` for `.athletePro` says "Unlock the full power of Tutrice" -- should reference "Faros".
**Fix:**
```swift
case .athletePro:
    return "Unlock the full power of Faros to push your training forward with data-driven precision."
```

### WR-04: ToastBanner uses DispatchQueue.main.asyncAfter instead of Task.sleep

**File:** `WorkloadApp/Components/ToastBanner.swift:29`
**Issue:** `DispatchQueue.main.asyncAfter` is not cancellable when the view disappears. If the user dismisses the parent sheet before the timer fires, setting `isPresented = false` on a potentially invalidated binding could cause unexpected behavior. Using a `Task` with `try await Task.sleep` in `.task {}` is the idiomatic SwiftUI approach and gets cancelled automatically.
**Fix:**
```swift
.task {
    let delay: Duration = isError ? .seconds(3) : .seconds(2)
    try? await Task.sleep(for: delay)
    withAnimation(.easeIn(duration: 0.15)) {
        isPresented = false
    }
}
```

### WR-05: HistoryTeaserBanner vertical padding is 14pt, violating 8pt grid

**File:** `WorkloadApp/Views/Subscription/UpgradeSheet.swift:420`
**Issue:** `.padding(.vertical, 14)` is not a multiple of 8pt. DESIGN.md requires all spacing to be multiples of 8.
**Fix:**
```swift
.padding(.vertical, 16)
```

## Info

### IN-01: SharpTextFieldStyle vertical padding uses 12pt (not 8pt multiple)

**File:** `WorkloadApp/Components/SharpTextFieldStyle.swift:9`
**Issue:** `.padding(.vertical, 12)` is not a multiple of 8pt per the design system. However, 12pt may be an intentional UX compromise for text field height -- flagging for awareness.
**Fix:** Consider `.padding(.vertical, 8)` (tighter) or `.padding(.vertical, 16)` (more generous), or document 12pt as an accepted exception for text inputs.

### IN-02: Multiple files outside review scope still use `.system()` fonts

**Issue:** At least 20 call sites across `DashboardView`, `ProfileView`, `TrainingProfileSheet`, `WeeklySummaryCard`, `ContextSwitcher`, `TemplateCarouselSection`, `TemplatePickerSheet`, `SignUpView`, and `DeltaIndicator` use `.font(.system(...))` instead of `Font.Tokens`. These are outside the Phase 13 file scope but represent remaining migration work.
**Fix:** Track these as follow-up items for the font migration task. A project-wide search for `.system(` in SwiftUI view files will produce the full list.

### IN-03: PrescribeWorkoutSheet double-applies text styling on notes TextField

**File:** `WorkloadApp/Views/PrescribeWorkoutSheet.swift:96-98`
**Issue:** The notes `TextField` has both `.font(.Tokens.label)` and `.foregroundStyle(ColorTokens.text2)` applied before `.textFieldStyle(SharpTextFieldStyle())`, which also sets font and foreground style. The outer modifiers may be overridden by the style, making them redundant.
**Fix:** Remove the redundant `.font(.Tokens.label)` and `.foregroundStyle(ColorTokens.text2)` on the TextField, or remove them from `SharpTextFieldStyle` if per-field customization is needed.

### IN-04: TemplateEditorSheet notes field has the same redundant styling

**File:** `WorkloadApp/Views/TemplateEditorSheet.swift:52-54`
**Issue:** Same pattern as IN-03 -- `.font()` and `.foregroundStyle()` applied before `SharpTextFieldStyle` which also sets them.
**Fix:** Same as IN-03.
