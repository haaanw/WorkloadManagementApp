## Component Inventory

### Social Login Section (LoginView + SignUpView)

This section is added below the existing "Sign In" / "Create Account" button, separated by an OR divider.

#### OR Divider
- Full-width horizontal layout: hairline rule -- "OR" text -- hairline rule
- Hairline: 0.5pt `ColorTokens.divider`
- "OR" text: 15pt DM Sans Regular, `ColorTokens.text3`
- Vertical padding: 24pt above and below

#### Sign in with Apple Button
- Use native `SignInWithAppleButton` from `AuthenticationServices`
- Style: `.signIn` on LoginView, `.signUp` on SignUpView
- Color scheme: `.dark` in light mode, `.white` in dark mode (follows Apple HIG inversion rule)
- Height: 48pt (Apple minimum is 44pt; 48pt aligns to 8pt grid)
- Full width minus 16pt horizontal padding each side
- 0pt corner radius: apply `.clipShape(Rectangle())` to override Apple's default rounded corners

#### Sign in with Google Button
- Custom button matching existing design system
- Background: `ColorTokens.surface`
- Border: 0.5pt `ColorTokens.divider`
- Corner radius: 0pt (Rectangle)
- Height: 48pt
- Layout: Google "G" logo (24x24pt, bundled as asset) + 8pt gap + "Sign in with Google" / "Sign up with Google" text
- Text: 15pt DM Sans Regular, `ColorTokens.text1`
- Horizontal padding: 16pt each side

#### Button Spacing
- 8pt gap between Apple button and Google button
- Both buttons placed inside a VStack with 16pt horizontal padding

#### Loading State
- Replace button label text with `ProgressView()` while authenticating
- Disable both social buttons and the email sign-in button during any auth operation

#### Error State
- Social auth errors display in the same error message area as email auth errors
- Use existing error pattern: `ColorTokens.zoneDanger` text, 13pt DM Sans Regular, left-aligned, 16pt horizontal padding, 12pt vertical padding, bordered by hairline dividers

## Interaction Contracts

### Social Login Flow

1. User taps "Sign in with Apple" -> native Apple auth sheet appears (system-managed)
2. On success: AuthService processes Apple credential, bootstraps Athlete, routes to MainTabView
3. On cancel: dismiss sheet, no error message (user-initiated cancellation)
4. On failure: display error in existing error area

1. User taps "Sign in with Google" -> redirect to Google OAuth in SFSafariViewController (Supabase handles)
2. On success: callback URL returns to app, AuthService processes token, bootstraps Athlete, routes to MainTabView
3. On failure: display error in existing error area

### Social Login Button Order (per Apple HIG)

On both LoginView and SignUpView:
1. Email fields + Sign In / Create Account button (existing, top)
2. OR divider
3. Sign in with Apple button (Apple HIG requires first position among social options)
4. Sign in with Google button
