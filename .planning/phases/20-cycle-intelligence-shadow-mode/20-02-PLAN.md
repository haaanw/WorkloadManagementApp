<objective>
Design the three evidence-gated cycle modifiers and the single reusable eligibility guard that governs all of them — all shipping **dark** behind a master `CycleModifierActivation.isEnabled = false` flag. Each engine gains an additive optional `cycleContext` parameter (nil → byte-identical to today). The modifiers are fully implemented and unit-tested, but with activation false they return the unmodified value; their would-be effect is computable so Plan 03 can log it in shadow.

Purpose: Deliver the modifier half of CYCLE-09/10's success criteria (ROADMAP criteria 2, 3, 4, 5, 6) as designed-but-inert behavior. The phase's safety contract — "no user-facing behavior change from modifiers until shadow confirms signal" — is enforced structurally: `CycleModifierGate` is the ONE place eligibility is decided (the 5-part guard of D-05), and `CycleModifierActivation.isEnabled` is the ONE switch that lets any modifier actually change a returned value. Both are off by default this phase. This also enforces D-09 (no change from phase alone) as a tested engine invariant across all three engines.

Output: `CycleModifierGate.swift` (pure guard + activation flag + explanation), additive `cycleContext` overloads on AutoregulationEngine / FatigueIndexEngine / ProgressionEngine implementing D-07/D-08, D-10, D-11 respectively, and comprehensive tests covering the gate, the yellow-only / green-and-red-never rules, the no-phase-alone invariant, and the nil-context identical-behavior regression for each engine.
