| Property | Value |
|----------|-------|
| Background | `ColorTokens.surface` |
| Border | `Rectangle().stroke(ColorTokens.divider, lineWidth: 0.5)` |
| Corner radius | 0pt |
| Shadow | none |
| Horizontal padding | 16pt |
| Vertical padding (top/bottom) | 16pt |
| Micro-caps header | "TRAINING PROFILE" -- `Font.Tokens.micro`, `.tracking(1.2)`, `ColorTokens.text3` |
| Title | "Set up your training profile" -- `Font.Tokens.body` (17pt Regular), `ColorTokens.text1` |
| Description | "Answer a few questions about your training to get estimated workload data right away." -- `Font.Tokens.label`, `ColorTokens.text2` |

**Placement:** After `WelcomeActionCard` (if visible) and before `EmptyStateCard` in DashboardView's VStack.

### 2. TrainingProfileSheet (Questionnaire Form)

**Pattern:** `.sheet(isPresented:)` presented from DashboardView and ProfileView. Single scrollable form. Not multi-step paged (D-04).

**Focal point:** The four required fields (Sessions per week, Average duration, Typical effort, Weeks at current level) are the primary interaction surface. The "Save Profile" button enables only when all four are valid, drawing the user's completion focus to that trailing nav action.

| Property | Value |
|----------|-------|
| Presentation | `.sheet(isPresented: $showTrainingProfile)` |
| Background | `ColorTokens.background` |
| Navigation | Inline navigation bar with title "Training Profile" (`.pageTitle` size via `.navigationTitle`) |
| Dismiss | "Discard Changes" leading nav button (text, `ColorTokens.text2`), "Save Profile" trailing nav button (text, `ColorTokens.text1`, disabled until all 4 required fields valid) |
| Corner radius | 0pt (system sheet chrome is acceptable) |
| Content | `ScrollView` > `VStack(spacing: 0)` with form rows |

**Layout structure (top to bottom):**

```
[Nav bar: Discard Changes --- Training Profile --- Save Profile]
[ScrollView]
  [Section: "REQUIRED" micro-caps header (12pt, .tracking(1.2), ColorTokens.text3)]
  [Row: Sessions per week]
  [Divider]
  [Row: Average duration]
  [Divider]
  [Row: Typical effort (sRPE)]
  [Divider]
  [Row: Weeks at current level]
  [Section divider (full-width)]
  [Section: "OPTIONAL" micro-caps header (12pt, .tracking(1.2), ColorTokens.text3)]
  [Row: Training age]
  [Divider]
  [Row: Schedule type]
  [Divider]
  [Row: Movement types]
  [Divider]
  [Row: Injury history]
[/ScrollView]
```

**Section labels:** "REQUIRED" and "OPTIONAL" use `Font.Tokens.micro` (12pt Regular) all-caps with `.tracking(1.2)` and `ColorTokens.text3`. This replaces the 19pt sectionHead, keeping the active type count to 4.

**Input control decisions (Claude's Discretion):**

| Field | Control Type | Rationale |
|-------|-------------|-----------|
| Sessions per week | `Picker` (wheel or menu) with range 1-14 | Discrete integer, bounded range. Menu picker matches ProfileView pattern |
| Avg duration (min) | `Picker` (menu) with 15-min increments: 15, 30, 45, 60, 75, 90, 120, 150, 180 | Preset values prevent unreasonable input. Menu picker for consistency |
| Typical sRPE | `Picker` (menu) with values 1-10, each labeled (1 = "Very Light", 3 = "Light", 5 = "Moderate", 7 = "Hard", 9 = "Very Hard", 10 = "Maximal") | Menu picker with descriptive labels helps athletes unfamiliar with sRPE scale. Show both number and label in each option |
| Weeks at current level | `Picker` (menu) with values: 1, 2, 3, 4, 6, 8, 12, 16, 24, 52 | Non-linear but common breakpoints. Labeled as "1 week", "2 weeks", etc. |
| Training age (optional) | `Picker` (menu) with range 0-30 years | Simple bounded integer |
| Schedule type (optional) | `Picker` (menu) with two options: "Steady" / "Periodized" | Binary choice, menu picker |
| Movement types (optional) | Multi-select grid or list using `SportType.allCases` with toggle checkmarks | Tap to toggle. Show checkmark next to selected items. Use existing SportType enum display names |
| Injury history (optional) | Tap to expand inline sub-form with `BodyRegion` multi-select + free-text notes field | Uses existing `BodyRegion` enum. Each selected region shows as a chip/tag. Optional notes `TextField` below |

## Interaction Contract

### Questionnaire Flow

1. User taps "Complete Profile" on TrainingProfileCard (dashboard) OR "Set up training profile" / "Edit Profile" in ProfileView
2. TrainingProfileSheet appears as `.sheet`
3. User fills required fields (all 4 must have non-default values for "Save Profile" to enable)
4. User optionally fills additional fields
5. User taps "Save Profile"
6. On save: call `ColdStartEngine.computeSeed(input:)`, create/update `TrainingProfile` with answers + seeded ATL/CTL, dismiss sheet (D-07)
7. Dashboard immediately reflects estimated values on next `DashboardViewModel.load()` cycle

### Dashboard Cold-Start Data Path

1. `DashboardViewModel.load()` checks: if no `WorkloadSnapshot` exists BUT `TrainingProfile` with seeded values exists AND `coldStartCompletedAt == nil` --> use seeded ATL/CTL for display
2. ATL/CTL/ACWR/TSB display with "EST" annotation
3. Workload trend chart hidden
4. FatigueIndex section shows "Building baseline..." card

### Switchover (Silent)

1. After each session save in `WorkoutPipeline.processSession()`, check threshold: `3+ weeks since seededAt` AND `8+ sessions logged`
2. If threshold met: set `coldStartCompletedAt = .now` on `TrainingProfile`
3. Next `DashboardViewModel.load()`: uses real `WorkloadSnapshot` data, "EST" labels disappear, chart appears, FatigueIndex computes normally (D-11, D-12, D-13)

### Bias Capture (Invisible)

1. At 8-week mark post-seeding, silently snapshot estimated vs actual ATL/CTL onto TrainingProfile bias fields (D-14)
2. No UI, no notification, no user-visible action

### Re-editing

1. User navigates to Profile > Training Profile > Edit Profile
2. TrainingProfileSheet opens pre-filled with existing answers
3. On save: re-runs `ColdStartEngine.computeSeed()` with updated answers, updates seeded values
4. If cold-start already completed: seeded values update but dashboard continues using real data (no regression)

## State Matrix

| State | TrainingProfile | coldStartCompletedAt | WorkloadSnapshot | Dashboard Shows |
|-------|----------------|---------------------|------------------|-----------------|
| Brand new user | nil | n/a | nil | WelcomeActionCard + TrainingProfileCard, ATL/CTL show "--", no chart |
| Profile completed, cold-start active | exists (seeded) | nil | nil or few | TrainingProfileCard hidden, ATL/CTL show seeded values + "EST", no chart, FatigueIndex shows "Building baseline..." |
| Switchover triggered | exists (seeded) | set to date | exists (8+) | Normal dashboard, real ATL/CTL, chart visible, FatigueIndex computes normally |
| Returning user (post-switchover) | exists | set to date | exists (many) | Normal dashboard, no cold-start UI visible |

## Accessibility

| Requirement | Implementation |
|-------------|---------------|
| VoiceOver for "EST" label | Combine value + annotation into single accessibility label: "ATL 142, estimated" |
| Form input labels | Each picker/field has `.accessibilityLabel` matching the question label |
| Touch targets | All form rows minimum 48pt height (12pt vertical padding + 17pt text + 12pt padding = 41pt minimum, add 7pt if needed) |
| Dynamic Type | Use `Font.Tokens` which are fixed-size custom fonts. Dynamic Type not supported per existing app pattern (custom font bundling). VoiceOver remains primary accessibility channel |
| Color contrast | All text/background combinations meet WCAG AA 4.5:1 per DESIGN.md verified tokens |
